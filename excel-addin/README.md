# Estimate Navigator

An Excel task pane that lists a workbook's bid items, checks and cost codes, inserts task rows from
templates, and gives the exact `est-estimate read-back` command to run. It reads only the open
workbook and sends nothing anywhere.

## Layout

- `core/`: pure logic, with no Office.js. Unit-tested with `node --test`.
- `panes/`: the Office.js task pane (`taskpane.html`, `main.js`, one module per tab, `excel.js` adapter).
- `brand/`: the generic `brand.json`, its schema, and `assets/` (logo and icons).
- `manifests/`: the committed generic manifest, generated by `est-addin manifest`.
- `site/`: the static store pages published with the add-in (`privacy.html`, `support.html`, `terms.html`).
- `scripts/`: `package.py`, which lays out a versioned site build, and `make_icons.py`, which draws
  the generic icons.

## Develop

1. Run the unit tests:

   ```bash
   node --test excel-addin/tests/*.test.js
   ```

2. Install a trusted localhost certificate. This uses development tools only and is not a repo
   dependency:

   ```bash
   npx office-addin-dev-certs install
   ```

3. Lay out the site locally, mirroring the published `/excel/addons/` tree:

   ```bash
   python excel-addin/scripts/package.py --version 0.0.0 --out dev/excel/addons
   ```

   Run it from the repo root. It uses this checkout's `packages/`, so no install of estimating-tools is needed. Rerun
   it after editing a pane or core file: it replaces `navigator/<version>/` each time. The result
   is:

   ```text
   dev/excel/addons/
     brand.json                    generic brand
     assets/                       generic logo and icons
     manifest.xml                  generic manifest (production URLs; see step 5 for a dev one)
     privacy.html, support.html, terms.html
     navigator/sample.xlsx         the sample workbook the empty state links to
     navigator/0.0.0/panes/        taskpane.html and the pane modules
     navigator/0.0.0/core/         core modules
   ```

   The pane loads `brand.json` from three levels above `panes/taskpane.html`, which is
   `dev/excel/addons/`, and the sample from two levels above, which is `dev/excel/addons/navigator/`.
   A branded deployment adds `dev/excel/addons/<slug>/brand.json`.

4. Serve `dev/` over https on port 3000:

   ```bash
   npx http-server dev -S -C ~/.office-addin-dev-certs/localhost.crt -K ~/.office-addin-dev-certs/localhost.key -p 3000
   ```

   Check that `https://localhost:3000/excel/addons/navigator/0.0.0/panes/taskpane.html` loads.

5. Generate a dev manifest:

   ```bash
   est-addin manifest --brand dev/excel/addons/brand.json \
     --app-url https://localhost:3000/excel/addons/navigator/0.0.0/ \
     --version 0.0.0.1 -o dev-manifest.xml
   ```

   The brand folder is derived from `--app-url`, two levels up (`/excel/addons/`), plus `--slug`
   when one is given. With no `--slug`, the manifest uses the generic brand at the root of that
   folder.

6. Sideload `dev-manifest.xml`:
   - **Excel for Windows:** put the manifest in a folder and share it, for example
     `\\<computer>\addin-catalog`. In Excel, open File → Options → Trust Center → Trust Center
     Settings → Trusted Add-in Catalogs. Add the share's path, tick **Show in Menu**, and restart
     Excel. Then go to Home → Add-ins → More Add-ins → Shared Folder and add Estimate Navigator.
   - **Excel on the web:** go to Insert → Add-ins → Upload My Add-in and choose `dev-manifest.xml`.
   - **Excel for Mac:** copy the manifest to
     `~/Library/Containers/com.microsoft.Excel/Data/Documents/wef/` (create the folder if needed),
     restart Excel, then go to Home → Add-ins and pick it under Developer Add-ins.

   After editing a pane file, reload the pane: right-click inside it and choose Reload, or close
   and reopen it.

## Manual test script

Excel cannot run in CI, so `panes/` has no automated tests. Run this script before every release on
**Excel for Windows, Excel for Mac and Excel on the web**. Record each platform's results, step by
step, in the PR.

1. **Build the sample.**

   ```bash
   est-estimate build packages/estimating-tools/estimating_tools/estimate_spec/packs/fieldbook/examples/demo-pipeline.estimate.yaml -o sample.xlsx
   ```

2. **Open it.** Open `sample.xlsx` and the pane. The pane shows the tabs Items, Checks, Codes,
   Insert and Read back, and "fieldbook pack" under the name.
3. **Items.**
   - There are three items and a DIRECT row, and the DIRECT row matches the Cost Summary total.
   - A click on an item opens its item sheet.
   - A double-click on an item selects its ITEM TOTAL MH cell.
   - The row for the active sheet is highlighted. Switch sheets in Excel and the highlight
     follows.
   - Hide an item sheet and click its row. The pane says "That item sheet is hidden. Unhide it to
     go there." Unhide the sheet again.
4. **Checks.**
   - The pass and fail counts match the Checks sheet's "Passing" row.
   - Change a crew count so that a check fails. Within a second, the count updates and the failing
     row is listed first.
   - A failing check for item `all` (the unbalance rule) reads "All items", and its button is
     disabled. Clicking it does nothing and shows no error.
   - Undo the crew change.
5. **Codes.**
   - Put the cursor in a task. The task's current code shows.
   - Search "valve" and click **Use**. The task header's code changes, and check 9 still passes.
6. **Insert.**
   - With the cursor on a CREW row, click New crew row. A blank crew row appears above the cursor,
     and the subtotal formula's range includes it.
   - With the cursor on SUBTOTAL, New crew row is refused with the END message.
   - New task inserts five rows below the subtotal.
   - Press Ctrl+Z (Cmd+Z on Mac) straight after an insert. Record whether it undoes the insert on
     this platform.
7. **Responsiveness.** Record how responsive each case is on this platform.
   - On the Codes tab, and then on the Insert tab, put the cursor in a task block and hold an arrow
     key down so the selection moves quickly. The pane must not flicker or lag behind the cursor.
     When you let go, it shows the right task and row within a moment.
   - Open the Read back tab on a large workbook: one with 60 item sheets, or one with a single
     stray value far down an item sheet. Excel stays usable while the pane checks, and the list
     shows "Rows checked at" a time when it finishes. A sheet longer than 20,000 rows is named as
     too large to check here, and does not block Copy command.
   - Edit a cell while the Read back tab is open. The pane does not re-scan the sheets; the time
     after "Rows checked at" changes only after you click Check again or re-enter the tab.
8. **Read back.**
   - While the workbook has unsaved changes, the list shows "Unsaved changes". Where `isDirty` is
     unsupported, it shows "Save the workbook first" as a reminder instead, and Copy command stays
     enabled.
   - Save, then click Check again. Every row is green.
   - Click Copy command. Paste it into a terminal in the workbook's folder and run it. It exits 0
     and reports the inserted rows.
9. **Hand-built workbook.** Open a workbook with a Summary sheet whose header row reads
   ITEM/DESCRIPTION, with cross-sheet references in columns A and E.
   - Only the Items tab shows.
   - Typed rows are grey and cannot be clicked.
10. **Blank workbook.** Open a new blank workbook. The empty state shows, with "Download a sample
    workbook" and "Help" links.
11. **Dark mode.** Switch the Office theme to dark. All text stays readable.
12. **Branded build.**
    - Load the pane with `?brand=<slug>`. The name and colours change.
    - Open a workbook built with a profile brand. It restyles the pane's interior only. The ribbon
      keeps the deployment's label.

## Branded builds

1. Write the brand from an org profile:

   ```bash
   est-addin brand --profile <dir> -o <site>/excel/addons/<slug>/
   ```

   - The profile's optional `brand:` section supplies the name, links, logo, icons, colours and
     heuristic settings.
   - A profile without a `brand:` section yields the generic brand.
   - A branded build needs all five PNG icons: `icon_16`, `icon_32`, `icon_64`, `icon_80` and
     `icon_128`.

2. Write the manifest:

   ```bash
   est-addin manifest --brand <site>/excel/addons/<slug>/brand.json \
     --app-url https://anvilrockroad.com/excel/addons/navigator/<version>/ \
     --version <v> --slug <slug> -o <site>/excel/addons/<slug>/manifest.xml
   ```

   The brand folder is derived from `--app-url`, two levels up, plus `--slug`. Here that is
   `https://anvilrockroad.com/excel/addons/<slug>/`.

3. Client files live only in the site deployment, never in this repo.
4. The client's admin deploys `manifest.xml` through Microsoft 365 admin center → Integrated apps
   → Upload custom apps.

## Releasing and the store

### 1. Before the first submission

These are for Brandon, not code.

- [ ] Confirm with the client whose original add-in this grew from that a public product is fine.
- [ ] Search the Microsoft Marketplace and the USPTO for "Estimate Navigator". If the name is taken,
      choose a new one and update `GENERIC` in `packages/estimating-tools/estimating_tools/addin/brand.py`.
      A drift test catches a stale `brand/brand.json` or `manifests/estimate-navigator.xml`.
- [ ] Create a Microsoft Partner Center account.
- [ ] Review `site/terms.html`. It is marked as a draft until then.
- [ ] When approving terms.html, set its effective date to the approval date and remove the draft
      comment.

### 2. Every release

- [ ] Build the tree:

  ```bash
  python excel-addin/scripts/package.py --version X.Y.Z --out dist/excel-addons
  ```

- [ ] Validate the manifest. It must pass:

  ```bash
  npx office-addin-manifest validate dist/excel-addons/manifest.xml
  ```

- [ ] Run the [manual test script](#manual-test-script) on Excel for Windows, Excel for Mac and
      Excel on the web.
- [ ] Upload the contents of `dist/excel-addons/` to `https://anvilrockroad.com/excel/addons/`.
      Keep the older `navigator/<version>/` folders: deployed manifests still point at them.
- [ ] When ready, point the client manifests at the new version:

  ```bash
  est-addin manifest --brand <site>/excel/addons/<slug>/brand.json \
    --app-url https://anvilrockroad.com/excel/addons/navigator/X.Y.Z/ \
    --version X.Y.Z.0 --slug <slug> -o <site>/excel/addons/<slug>/manifest.xml
  ```

### 3. Store submission (generic build only)

- [ ] In Partner Center, create an Office add-in and upload `dist/excel-addons/manifest.xml`.
- [ ] Fill in the listing:
  - the 300 px icon, `assets/icon-300.png`
  - screenshots of the five tabs
  - the privacy, support and terms URLs: `https://anvilrockroad.com/excel/addons/privacy.html`,
    `support.html` and `terms.html`
- [ ] Testing notes: "Download `https://anvilrockroad.com/excel/addons/navigator/sample.xlsx`, open
      it, open Estimate Navigator from the Home tab."

### 4. Updates

- Static code changes ship by uploading a new `navigator/<version>/` folder and moving the
  manifest's URL to it. Moving the URL is a manifest change.
- Any manifest change is resubmitted: URL, name, icons, permissions or requirement sets.

### 5. Migrating the original client pane

- [ ] Build its brand from their profile, with a `brand: heuristic:` section whose values equal
      `DEFAULT_PROFILE` in `core/heuristic.js`:

  ```bash
  est-addin brand --profile <their profile> -o <site>/excel/addons/<slug>/
  ```

- [ ] Write its manifest with `est-addin manifest ... --slug <slug>` (see
      [Branded builds](#branded-builds)) and publish both under `/excel/addons/<slug>/`.
- [ ] Redirect the old `bid-item-list.html` URL to
      `/excel/addons/navigator/<version>/panes/taskpane.html?brand=<slug>`.
- [ ] Their admin swaps the manifest in the Microsoft 365 admin center.
- [ ] Test against one of their real workbooks. Do not commit it.
